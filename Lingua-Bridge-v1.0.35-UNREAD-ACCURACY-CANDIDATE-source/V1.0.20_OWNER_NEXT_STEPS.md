# Lingua Bridge v1.0.20 owner next steps

The live Vercel logs showed the intermittent red banner was caused by Gemini HTTP 429 rate limiting during a burst of automatic message translations. It was not a Burmese-language mapping failure.

## Apply both halves of the fix

1. Deploy the server fix by running `DEPLOY_VERCEL_v1.0.20_RATE_LIMIT_FIX.bat` from this exact folder.
2. Build the Windows candidate by running `BUILD_WINDOWS_v1.0.20_RATE_LIMIT_STABILITY_NO_NSIS.bat`.
3. Use the v1.0.20 desktop candidate for testing. The old desktop can still generate request bursts even when the server is fixed.
4. Confirm the toolbar shows `DeepL ✓ · Gemini ✓`.
5. Test English -> Myanmar, Myanmar -> English, and a second broad language such as Thai or Vietnamese.

## What changed

- Host settings are only re-sent when they actually changed.
- Automatic scans translate a small recent-message window instead of forcing 40 messages after UI refreshes.
- Broad-language incoming translations run one at a time and are paced.
- Duplicate queued translations are coalesced.
- Transient incoming failures retry later before showing an error.
- Provider 429/5xx retries use bounded exponential backoff and Retry-After when available.
- Gemini can try the next configured model after a bounded model-specific 429.
- Device last-seen writes are throttled to reduce Prisma write conflicts.
- `.vercelignore` prevents Windows build artifacts from causing Vercel 100 MB upload failures.

## Important quota note

Gemini Free Tier has real RPM/RPD limits. This release removes Lingua's artificial burst behavior, but it cannot create unlimited free API quota. If a project truly exhausts its daily quota, translation must wait for quota reset or use another configured broad-language provider / a paid tier.
